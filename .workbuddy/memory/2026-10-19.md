### 核心结论
1. 命题非无人区：arXiv 2603.21334《Software as Content》已把「线性聊天三限制」（representation mismatch / interaction entropy / ephemeral interaction state）写成论文，并点名批评 Claude Artifacts 与 OpenAI Canvas 只是 display surface 而非双向通道。
2. 「无限画布 + AI」已不稀缺（Flowith、即梦、Pixmax、tldraw 生态）。稀缺的是多态节点——市面上画布节点都还是内容块，不是自带交互形态的对象。
3. 最大撞车风险：微软亚研院 **Huabu**（命题几乎重合）、**Fellou CE**（空间化 agentic browser，SaC 论文作者邮箱即 fellou.ai）。
4. 协议层已成熟并可借力：AG-UI（传输，CopilotKit）／A2UI（Google，声明式 UI 格式，flat adjacency list 可增量流式）／MCP Apps（Anthropic，iframe 沙箱）／OpenAI Apps SDK。建议不自建 UI 描述语言。
5. 建议的差异化窗口：**多态节点 × 空间组合**（表格筛选驱动图表、决策分支激活下游节点）——单页 Generative UI 与纯画布都做不到。

### 待办（调研中识别的缺口）
- Wuji 当前缺「信任线索」（trust cues）与「人工审批检查点」——Wavespace 五原则中的第 2、3、4 条完全为空。
- 可参考 PenEcho 的「AI 草案 vs 已确认」两态设计来实现信任线索。
- 画布引擎不必自写：tldraw（48k★）已有 Agent Kit / Chat Kit / Branching Chat Kit。

## 多态节点形态与交互契约（交付 NODES.md）

### 已确认的现有实现基线（读 prototype/index.html 得出）
- node schema 极简：`{ id, type, title, body, x, y, updated }`
- `nodeMeta` 只是 type→label 映射，四种类型（intent/agent/note/task）**共用同一张纸卡**，无多态 → 印证「节点是内容块」的判断
- link 只有 `{ from, to }`，**无语义**

### 契约要点
- 八种形态：Intent / Note（兜底）/ Trace / Evidence / Table / Plan / Decision / Action
- Trace 是与 Flowith 的分水岭：Fellou 时间线回放、Manus 执行日志、Flowith 节点链都是「给你看」，Trace 是「给你改」（可暂停、跳过、改参数从某步重跑）
- 补齐 Wavespace 原则 3/4：Evidence 承载 trust cues，Action 承载 approval checkpoint（含影响范围与可逆性）
- 连线四语义：`derived`（生成）/ `binds`（实时绑定，A 变 B 变）/ `triggers`（事件触发）/ `supports`（证据支撑）。binds + triggers 是「空间组合」的发动机
- 形态路由：有副作用→Action；步骤序列→Trace；互斥选项→Decision；有序可执行项→Plan；≥2 条同构记录→Table；引用来源→Evidence；其他→Note
- 对接 A2UI：八形态映射八组件（DataTable/CheckList/OptionCards/ApprovalCard/StepTimeline/Citation/RichText/GoalHeader），宿主控制样式

## 方案代价批判（用户问「这种交互方案的缺点是什么」）
未落成文档，结论在对话内 + 一张代价地图（SVG，左列可缓解 / 右列结构性）。

### 结构性缺点（只能取舍，无法靠工程消除）
1. **空间没有阅读顺序**——画布把时间顺序换成空间位置，但位置无天然先后；注意力成本从「滚动」转移到「导航」，>15 节点后开始失控。
2. **无限 = 永不收口**——缺「完成」语义与版本，心理闭合感缺失。
3. **多态会削足适履**——文本是通用降级层，半结构化内容强套形态会困住用户；形态路由误判的代价高于纯文本。
4. **隐式依赖让人不敢动**——binds/triggers 链一长，用户无法预测改动影响面（同 Excel 公式链，至今无解）。
5. **概率 AI × 确定性绑定的根本张力**——绑定的是不稳定的东西，同一输入重跑可能得不同结果。
6. **只在复杂任务上划算**——简单任务是纯负担，且 demo 难以自证（demo 只能演示简单任务）→ 市场天然窄、偏专业用户。
7. 附带：丢掉叙事（来龙去脉）、丢掉低成本「随便说一句」、状态爆炸（undo/复现/分享成本远高于聊天）、多人协作（图结构 + 多态内部状态的 CRDT 成本高）、无障碍与键盘不友好。

### 可缓解（工程问题）
空白画布恐惧 / 节点检索（缩略图·搜索·聚焦）/ 平移缩放操作成本 / 八形态一致性（形态注册表+设计系统）/ 依赖可视化（影响范围高亮·脏态标记）/ 移动端需另做线性视图。

### 关键判断
Wuji 最原创的部分（组合驱动）恰好是风险最深处——因为「隐式依赖」是软件史反复出现且未被解决好的旧问题。第二阶段做 binds 运行时前，必须先做「影响范围可见」，否则会直接撞上第 4 条。
